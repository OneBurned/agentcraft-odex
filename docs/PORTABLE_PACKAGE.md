# Нейтральный переносимый пакет

Пакет A11 содержит существующий observer-мост, мод, Fabric API, Node, нейтральные
инструкции и примеры личностей. Динамическая команда из [TEAM_MODEL.md](TEAM_MODEL.md)
реализуется отдельно; эта сборка не объявляет её готовой. Локальный профиль владельца
репозитория не читается и не копируется сборщиком. Установка и публикация — отдельные действия.

## Сборка

1. Собрать мод: из `mod` выполнить `gradlew.bat build --console=plain` с JDK 25.
2. Из корня: `node tools/build-portable.mjs <новая-папка>`.
3. Успех означает наличие `PACKAGE-READY.json` и нулевой код выхода. При любой ошибке
   папка считается неполной; сборщик не перезаписывает уже существующий каталог.
4. Повторная проверка: `node tools/audit-portable.mjs <папка-пакета>`.

Сборщик берёт версию из `mod/gradle.properties`. Проверка утечек обязательна и выполняется
перед записью отметки готовности. Нельзя распространять использованную установку:
после запуска в `data/portable` и `logs` уже появляются личные данные. Нужно собрать новый пакет.

Вместо `tools/klava`, личного `tools/templates/personas.json` и исходного описания cast
используются `tools/portable-templates`. В JAR заменяются только cast и названия шести
дополнительных скинов; классы, изображения и вложенные библиотеки сохраняются по содержимому.
Русская и английская инструкции находятся в `tools/portable/README.ru.txt` и `README.en.txt`.
`SOURCES.txt` фиксирует необходимость подтверждения пользователем прав на шесть PNG перед
публичным распространением. Наличие этих файлов в сборке не подтверждает права на них.

Личные схемы по умолчанию отсутствуют. Только явный `--include-schematics <папка>`
добавляет `.schem` и `SOURCES.txt` из указанной папки; прежний неименованный аргумент
каталога схем отклоняется. Это отдельная частная сборка с `privateSchematics: true`.
Её проверяют с `--allow-schematics`; остальные правила утечек остаются обязательными.
Схемы не добавляются в JAR и не выбираются автоматически из папки Minecraft.

## Что проверяет сканер

`tools/audit-portable.mjs` проверяет имена и содержимое файлов независимо от расширения,
UTF-8/UTF-16LE, экранированные строки JSON/JS, файлы внутри ZIP/JAR и их метаданные,
включая вложенные Fabric JAR. Ограничения размера, глубины и числа файлов защищают
от неограниченной распаковки. Повреждённый или неподдерживаемый архив, ссылка вместо
обычного файла, обход каталогов и неоднозначные имена в ZIP завершают проверку ошибкой.

Проверяются пользовательские абсолютные пути, имена наших проектов/личностей,
UUID разговоров и сессий, почтовые адреса, файлы состояния, памяти, истории,
авторизации и схемы без явного разрешения. Диагностика содержит относительный путь
и правило, но не найденное секретное содержимое; чувствительные имена файлов скрываются.
Это проверка известных признаков и структуры, а не гарантия распознавания любого
произвольного секретного текста или стеганографии в изображении.

Узкие исключения не скрывают личные данные:

- В коде сканера перечислены публичные UUID протокола WebSocket, Windows, валидатора
  и namespace SDK, а также вычисляемые пути домашней папки и публичный пример пути из SDK.
  Любой другой UUID или пользовательский путь отклоняется.
- `user@agentcraft.local` — фиктивная техническая Git-идентичность, а не пользовательский аккаунт.
- `tools/portable-vendor-hashes.json` закрепляет точные пути и SHA-256 публичных файлов:
  Node, его лицензия, лицензия ws, атрибуция Java-WebSocket, иконки и FakePlayer Fabric API.
  Только для byte-identical файлов разрешены публичные контакты/UUID. Личные пути,
  проекты, личности и файлы состояния исключением не покрываются. Изменение хотя бы
  одного байта отменяет исключение; обновление зависимости требует проверки происхождения
  и обновления списка, а не автоматического принятия нового хэша после ошибки сканера.

Технические идентификаторы `marlow`/`wren`, имена ресурсов скинов и namespace `klava`
пока сохраняются для совместимости существующего протокола; они не импортируют личность,
аккаунт или историю владельца. Экранные подписи мостов нейтральны; имя персонажа пользователя
по-прежнему читается из его профиля. Правила лицензий сторонних компонентов сохраняются.

## Запуск и свои PNG

`Connect-Codex.ps1` выполняется из выбранного Desktop-чата и пишет привязку только в
профиль пакета. `Start-Bridge.ps1` задаёт этот же путь явно, не подхватывает глобальную
привязку другого профиля и не использует чужой мост на занятом порту. Для нового профиля
копируется нейтральный пример личности; существующий `personas.json` не перезаписывается.
Параметр `-Repository` выбирает локальный Git-проект. Запуск сам по себе не запускает очередь.

Импорт через пульт: «Внешность» → «Загрузить PNG…» → путь к PNG 64×64 до 512 КиБ →
«Применить». Изображение копируется в `config/agentcraft-skins/<SHA-256>.png` папки игры.
Импортированный файл не зависит от исходного пути. Старые встроенные PNG 64×32 имеют
отдельное преобразование; пользовательский импорт остаётся 64×64.

## Проверки

- `node --test tools/test/audit-portable.test.mjs` — чистые данные, реальные подложенные
  признаки утечек, CLI exit code, вложенные JAR, повреждение архивов, ZIP comments,
  флаг схем и аннулирование исключения лицензии при изменении байта.
- `node tools/test/studio-package.mjs <папка-пакета>` — отдельный профиль/порт, состояние
  очереди и история сессии на синтетических данных, без сообщений реальным агентам.
- `tools/test/PortableSkinCheck.java` запускается Java 25 с готовым JAR первым в игровом
  runtime classpath. Проверяет источник загруженного класса, фактический импорт PNG,
  независимость от исходного файла и отклонение неправильных изображений. Classpath
  получают из Gradle/Loom окружения; проверка не запускает окно Minecraft.

Отдельно проверяются неизменность шести PNG в готовом JAR, PowerShell-синтаксис запускателей,
проверки моста и сборка мода. Отрисовка, масштаб интерфейса и ручной выбор PNG в Minecraft
требуют отдельной игровой проверки и не следуют из успешной автоматической проверки импорта.
