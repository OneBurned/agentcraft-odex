## Что означает результат

**Тест / пройден** означает выполнение указанного автоматического сценария.
Там, где транспорт модели подменён, проверяются реальные очереди, адаптеры,
маршрутизация и файлы, но не ответы сервиса и не авторизация аккаунта.
Тестовая нативная история Claude — специально созданные записи, не реальные беседы.
**Открыто** означает, что требуемый пользовательский сценарий не подтверждён;
успешный тест отказа не превращает недоступную функцию в работающую.

## Пробная установка: точные ограничения

`portable-trial.mjs` создаёт временные каталоги выпуска, игры, установки и пустого
аккаунта. Он использует реальный механизм копирования/журналирования A12 и запускает
настоящий установленный `observer-main.mjs` отдельным процессом, на отдельном порту.
Принадлежность процесса проверяется по PID в его runfile до подключения и остановки.
После проверки временная установка удаляется; распространяемый источник повторно
проверяется скриптом утечек. Использованная установка не считается чистым пакетом.

Для этой изолированной операции список процессов передаётся тестовой функцией:
личный мост остаётся запущенным, а штатный Setup консервативно запрещает установку
при любом обнаруженном мосте. Обхода в CLI или переменной окружения не добавлено.
Реальный `Get-CimInstance` проверяется отдельно в `setup-package.mjs`; отказы при
Minecraft/мосте/live PID проверяются автоматическими сценариями. Такая проба не
заменяет интерактивную установку со штатным процессным контролем — она входит в t53.

### Диагностика блокера Codex CLI (2026-10-09)

Локальный журнал sandbox уточняет причину: проверка read/execute ACL для
служебного `cua_node/.../bin/node_repl.exe` возвращает Windows error 32
(файл занят другим процессом). Это воспроизводится вне AgentCraft командой
`codex sandbox -P :workspace ... Write-Output AGENTCRAFT_SANDBOX_OK`.
Удаление унаследованных путей окружения и отключение пользовательской конфигурации
в отдельном `codex exec --ignore-user-config --sandbox workspace-write` не устранили
сбой. Живой exec вернул command_execution с exit_code=-1, но затем turn.completed
и общий exit code 0. Исходный проект остался без изменений; ревью не запускалось.
Процессы других разговоров не завершались, sandbox не ослаблялся.

В исходниках исправлена диагностика: распознанная ошибка запуска sandbox сохраняется
как ошибка адаптера, а неверный финальный отчёт текущей попытки показывает причину
на доске. В подсказке разработчику явно перечислены значения ci, включая unknown
для незапущенных проверок. Установленный личный мост и QA-пакет пока не обновлены.
Проверки исходников: 77 тестов codex-cli/role-queue прошли; после уточнения
сохранения ошибки при turn.failed прошли ещё 3 целевых сценария (15 остальных
в этом повторе отфильтрованы). TypeScript --noEmit и git diff --check прошли.

Внешняя проверка сохранена вне Git:
`Documents/AgentCraft-Trial-t53-20261009/Check-Codex-Sandbox.cmd`.
Пользователь запустил файл после закрытия приложения. В
`providers/sandbox-external-result.txt` снова ошибка setup refresh; новый журнал
называет занятый `node.exe`. Закрытие окна не является подтверждённым исправлением.

Причина подтверждена исходниками OpenAI: старая реализация запрашивает
MAXIMUM_ALLOWED при обновлении ACL работающих EXE/DLL. Исправление
[dd12f892 / PR 51822](https://github.com/openai/codex/pull/51822)
ограничивает этот способ открытия каталогами. Исходники тега `rust-v0.162.0`
исправления ещё не содержат; `rust-v0.163.0-alpha.2` содержит.

Официальный `codex-package-x86_64-pc-windows-msvc.tar.gz` версии 0.163.0-alpha.2
скачан отдельно в providers; SHA-256 сверена с GitHub Release:
`422b377636e0085a839b475b39af43fa5ad789912684a21fc294ed1759c54658`.
Команда вывода маркера с `sandbox -P :workspace` прошла с кодом 0 и
`AGENTCRAFT_SANDBOX_OK`, пока приложение оставалось открытым. Политика sandbox
не менялась. Это отдельная тестовая CLI; бинарники приложения, личные подключения
и распространяемый AgentCraft-пакет не заменены.

Повтор установленной пары ролей с новой CLI сохранил старую неуспешную t2 как
cancelled и создал t3 с теми же разработчиком, ревьюером и тестовым проектом.
Codex создал `sum.mjs`/`sum.test.mjs`, выполнил 3 успешных node:test-проверки.
Независимый повтор этих тестов также прошёл. Коммит остановлен реальным запретом
записи `.git/index.lock` в workspace-write. Оба файла сохранены неотслеживаемыми;
HEAD не изменён, ревью не стартовало. Теперь корректный blocked-отчёт с ci=pass
принят доской и показывает исходную причину. Свидетельство:
`providers/role-pair-retry-result.json`. Эта промежуточная попытка не прошла.
Это отдельное ограничение разрешений, а не возвращение исправленной ошибки runtime.

Пользователь отдельно разрешил запись только в `.git` одноразового тестового проекта.
В его `.codex/config.toml` добавлен точный абсолютный путь через
`sandbox_workspace_write.writable_roots`; конфигурация исключена из Git локально
через `.git/info/exclude`. Глобальная конфигурация не менялась. Первая попытка после
этого всё ещё упиралась в оставшиеся deny ACL от прежних запусков sandbox:
`providers/role-pair-git-write-before-acl-result.json`.

SDDL тестовой `.git` сохранён в `providers/git-acl-before-authorized-write.sddl`.
Сняты только четыре явных deny ACE двух capability SID, сопоставленных с этим
тестовым workspace; остальные ACL и другие каталоги не менялись. Проверка записи
в тестовую `.git` прошла; отдельная проба с профилем на базе `:workspace` отклонила
запись рядом с проектом. Затем восстановлена указанная локальная настройка
`sandbox_workspace_write`, с которой выполнена реальная пара ролей.

Неотслеживаемые файлы предыдущих попыток сохранены вне проекта перед повтором;
коммит за модель вручную не выполнялся. Codex самостоятельно создал
`50d0522b6c1e53e599c8e569404aa4ffd88f4857`, Claude принял именно этот HEAD.
`providers/role-pair-git-write-result.json`: passed=true, stage=done, ci=pass.
Оба агента завершили работу; тестовый мост остановлен, личный снова запущен на 7878.
Личные подключения и распространяемый пакет не заменены. Minecraft не запускался.
