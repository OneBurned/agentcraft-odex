# Удалённый чат Codex через мост Windows

Мост и Minecraft работают на Windows. Коннектор из локального чата Codex может
выбрать существующую беседу на подключённом SSH-хосте приложения. Адрес моста
остаётся `ws://127.0.0.1:7878`: публичный порт, новый SSH-туннель и отдельный
app-server для этого не создаются.

## Подключение

1. В пульте создать отдельного Codex-агента или явно выбрать существующего.
2. Получить точные `threadId` и `hostId` через список чатов приложения. Имя компьютера
   не заменяет host ID: поддерживаются `local` и `remote-ssh-codex-managed:<UUID>`.
3. Из локального Windows-чата Codex, имеющего `CODEX_APP_TOOLS_PIPE_PATH` и
   `CODEX_THREAD_ID`, сначала проверить цель:

   ```powershell
   node --import ./foreman/node_modules/tsx/dist/loader.mjs tools/connect-codex-chat.ts --thread <UUID> --host <hostId> --check
   ```

4. После проверки выполнить ту же команду с `--agent <agentId>` вместо `--check`.
   В установленном пакете используются `runtime/node.exe` и `connect-codex-chat.mjs`.
   Обёртка `Connect-Codex.ps1` принимает `-Agent`, `-Port`, `-ThreadId`, `-HostId`,
   `-Check`. `--thread` и `--host` задаются вместе. Без них выбирается текущий
   локальный чат, как раньше. `--check` не меняет профиль и не отправляет сообщения.

Windows-коннектор сначала читает выбранный чат и проверяет возвращённый UUID.
Чат Windows сохраняется как `callerThreadId`, а целевые `threadId/hostId` идут в
аргументы вызова. Контекст вызывающего чата не подменяется удалённой беседой.
Смена pipe для прежней пары host/thread идёт через `connection.refreshCodex`;
смена цели — через `connection.bind`. Свежие pipe вида `codex-app-tools-*` и прежние
`codex-browser-use-*` поддерживаются только в локальном пространстве Windows named pipes.

Сессии резервируются по host ID и thread ID. Курсор сообщений и сохранённая пауза
не переносятся между одинаковыми UUID на разных хостах. Старые курсоры без host ID
считаются локальными. После перезапуска приложения коннектор нужно повторить из
локального чата, чтобы обновить адрес Windows pipe.

## Pause и Stop

Команды ищут владельца именно целевого host/thread. Для удалённых follower-команд
используются host ID в IPC-конверте и версии протокола приложения 26.1021.3705:
clear-queued-messages v2, interrupt-turn v5. Локальная остановка сохраняет прежние
версии v1/v3. Успех всё равно требует последующего чтения статуса беседы.

В живой проверке 24 октября 2026 Windows-приложение возвращало `no-client-found`
для удалённого владельца, в том числе после открытия чата и во время активного
тестового ответа. Поэтому **Pause/Stop из игры для проверенного удалённого чата
не работают**. Мост возвращает явную ошибку и не записывает успешную паузу или стоп.
Останавливать такую работу нужно кнопкой Stop в самом Codex. Возобновление кнопкой
игры возможно только после подтверждённой игровой паузы; ложная пауза его не разрешает.
Поддержку удалённого управления в другой версии приложения нужно проверять отдельно.

## Проверка и личный профиль

В личный профиль добавлен отдельный агент **Wahda**, подключённый к удалённой беседе
«Изучить проект и правила». Кадеин сохранил локальный чат, Клава — собственную сессию.
Мост обновлён, JAR Minecraft не менялся. Перед установкой сохранена резервная копия
профиля и заменяемых файлов в `AgentCraft-Portable/backups/remote-chat-*`.

Подтверждены чтение, отправка и получение финала через адаптер (`AGENTCRAFT_REMOTE_OK`)
и через установленный мост с новым агентом (`WAHDA_BRIDGE_OK`). Тестовая работа
не меняла файлы удалённого проекта. Очередь оставлена на паузе.

Это проверка общения и отображения активности. Автоматическое выполнение очереди
в Linux-каталоге Wahda не проверялось: локальные Windows-пути проектов, отчётов и
permits не становятся доступными удалённой сессии от одной привязки чата.
Межагентные инструменты, требующие локальный permit, также не получают автоматически
доступ с удалённого хоста.

Проверки: TypeScript, 74 целевых теста схем/IPC/адаптера/runtime и тест PowerShell-обёртки.
