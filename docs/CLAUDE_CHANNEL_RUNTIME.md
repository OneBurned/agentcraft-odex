# Терминальный канал Claude для AgentCraft

Экспериментальное подключение `claude-channel` соединяет команду Foreman с одной
открытой терминальной сессией Claude Code. В игре и в этом терминале используется
один UUID и одна история. Поддерживаются сообщения, планирование и ревью;
разработка через этот транспорт отклоняется до отправки. Для разработки остаётся
обычное подключение `claude-code` с SDK.

Это локальная разработка собственного канала, а не готовый публичный плагин.
Default Setup и публичная сборка не предлагают этот launcher. Личный профиль,
существующая очередь и разговор Клавы автоматически не переключаются. Перенесённая
старая парная очередь продолжает отклонять смену подключения; её миграция — отдельная
операция. Minecraft-мод не меняется: используются существующие сообщения и кнопки.

## Запуск разработчиком

1. Использовать профиль с новой командной очередью. Остановить работу выбранного
   агента и закрыть прежний терминал/Code. Рабочее пространство должно содержать
   обычные `access.json`, `CLAUDE.md`, `PROJECTS.md`, `MEMORY.md`, `conversation.json`
   и существующую сессию в локальной истории Claude.
2. Через действующий операторский `connection.bind` сохранить новое неизменяемое
   подключение того же агента. Пример JSON для `tools/studio.mjs connection.bind --file
   <private-file.json> --port <port>`:

   ```json
   {
     "id": "agent_id",
     "revision": 1,
     "connection": {
       "provider": "claude",
       "transport": "claude-channel",
       "workspace": "C:/path/to/claude-workspace",
       "sessionId": "00000000-0000-4000-8000-000000000001",
       "executable": "C:/path/to/claude.exe"
     }
   }
   ```

   Подставить текущую ревизию команды, ID агента и реальный UUID. Не редактировать
   активный connection-файл вручную. Планировщик не имеет права выполнять bind.
3. Из `foreman` открыть обычный терминал:

   ```text
   node --import tsx src/claude-channel-launcher.ts --profile-dir <profile> --agent <id>
   ```

   В приватном собранном пакете entry — `foreman/src/claude-channel-launcher.mjs`;
   запускать комплектным Node. Сохраняются штатные trust/development-подтверждения.
   Пока они не пройдены, мост показывает, что канал не готов.
4. Оставить это окно открытым. Писать можно прямо в нём либо из игры. Отдельный
   `claude --resume`, `/bg`, `/fork` и перенос в Desktop не являются входом в этот
   канал. Для смены подключения закрыть launcher после остановки Claude.

Launcher запускает только MCP `klava` с существующими ограничениями доступа и
`agentcraft.reply`. Встроенные инструменты отключены (`--tools ""`), strict MCP,
permission mode default, hooks отключены, пользовательские источники настроек не
подмешиваются. Доступ к проектам, памяти, планированию и сообщениям других агентов
по-прежнему ограничивают настройки рабочего пространства и отдельные permits.

## Pause, Stop и продолжение

- **Пауза** сохраняет ожидающий запрос, запрещает его поздний ответ и завершает
  запущенный launcher процесс Claude вместе с подтверждёнными потомками.
- **Стоп** делает то же, но удаляет ожидающий запрос из состояния адаптера.
  Сохранённая история разговора остаётся.
- **Продолжить** сначала открывает Claude с тем же `--resume UUID`. После штатного
  development-подтверждения в терминале нажать «Продолжить» ещё раз. После паузы
  отправляется новый ID со ссылкой на прерванный запрос и указанием учитывать уже
  выполненные действия; после Stop открывается свободный разговор без повтора задачи.
- После остановки **exit + Enter** (или Ctrl+C в обычном терминале) закрывает сам
  launcher и освобождает блокировку. В тестовом PTY проверен именно `exit`.

После паузы ответа, начатого напрямую в терминале, «Продолжить» открывает историю;
просьбу продолжить такой ответ нужно ввести в терминале. Повторная отправка из игры
применяется только к сохранённому игровому запросу.

Успех Pause/Stop возвращается только после проверки дерева процессов владельцем.
Ошибки проверки, живые потомки, пропавший launcher или чужая сессия в той же папке
не трактуются как успешная остановка. Чужие процессы не завершаются. Если `/bg`
перенёс работу во внешний daemon, её необходимо закрыть в Claude вручную.

## Доставка и восстановление

Локальный mailbox находится в `<workspace>/.agentcraft-channel`. Сетевого
слушателя нет. Привязка включает профиль, агента, UUID, владельца launcher и
поколение процесса; общий conversation lease исключает второй штатный launcher.

Адаптер сохраняет запрос до помещения в mailbox. MCP создаёт эксклюзивный claim
и выполняет fsync **до** notification. Один ID не отправляется повторно, даже после
перезапуска MCP. Одинаковый повтор `reply` возвращает receipt без второй записи;
другой текст с тем же ID и ответ на отменённое/чужое сообщение отклоняются.

Запись notification не означает получение ответа. Финал поступает в очередь только
после сохранённого `reply` и подтверждённого `idle` исходного CLI. История игры
преобразует channel envelope в исходный текст игрока, а reply tool — в полный ответ;
служебное послесловие Claude не дублируется. Обычные сообщения терминала читаются из
той же истории SDK.

После аварии между claim и notification результат неопределён. Мост не повторяет
работу автоматически. Если сменилось поколение канала, запрос остаётся на паузе;
перед продолжением нужно проверить историю. После явного продолжения создаётся
новый ID: это не гарантия однократности побочных действий модели.

Receipt завершения сохраняется до callback очереди. При аварии между этими шагами
callback может не пройти: ответ остаётся в mailbox/истории, а состояние задачи
нужно проверить. Автоматического повторного callback нет. Это семантика at-most-once,
не транзакционная exactly-once доставка между Claude и очередью.
