# Перенос существующей команды (A4 / t43)

Перенос выполняется отдельной командой до запуска обновлённого моста. Сам запуск моста
не меняет старый профиль. Чистый профиль по-прежнему создаёт пустую команду.

`marlow` сохраняет ID и становится Codex-разработчиком; `wren` сохраняет ID, имя и
подключение Claude с ролями планировщика и ревьюера. Сохраняются имена, цвета, скины,
параметры внешности, включение/видимость, `personas.json`, история, задачи, исполнители,
заметки, `replyAgentId`, личные паузы, приостановленные карточки и ожидающий ответ.
ID в рабочих местах и личных точках не меняются.

Четыре неиспользуемых стандартных персонажа не входят в новую команду. При обнаружении
настроек, назначения, сессии, личной памяти, скина или игровых мест у другого персонажа
перенос отказывает и сообщает ID: нужно отдельное решение, а не удаление данных.
Исходный состав остаётся в резервной копии.

## Подготовка и запуск

1. Приостанови очередь. Закончи или останови активную работу Codex/Claude;
   приостановленные карточки и ожидающие ответы можно оставить.
2. Верни общий разговор Claude из терминала/Code существующей командой возврата.
   Наличие `conversation-lock.json`, включая старую блокировку, запрещает перенос.
   Перенос не снимает чужую блокировку и не создаёт новый разговор.
3. Сохрани мир, закрой Minecraft и останови мост. Codex оставь открытым: прежний чат
   проверяется чтением состояния без отправки сообщений.
4. Выбери новую папку копии вне профиля, игры и папки Claude. Не помещай её в Git
   или распространяемый пакет.

Из `foreman/` в исходниках:

```powershell
node --import tsx ../tools/migrate-team.ts apply `
  --profile-dir "D:/AgentCraft/data/observer" `
  --game-dir "D:/Minecraft/Fabric" `
  --codex-binding "D:/AgentCraft/codex-chat.json" `
  --backup-dir "D:/AgentCraft-backups/before-team"
```

Подставь абсолютные пути прежнего профиля, Fabric-папки игры и используемого
`codex-chat.json` (в том числе из `AGENTCRAFT_CHAT_CONFIG`, если он задан).
Папка Claude читается из `claude-workspace.json`. В переносимом пакете замени
`node --import tsx ../tools/migrate-team.ts` на `./runtime/node.exe ./migrate-team.mjs`.

Команда проверяет владельца профиля, очередь, задачи, закрытую игру, состояние Codex
и наличие нативной сессии Claude. Неизвестное состояние Codex — отказ. Модель не
запускается. Windows-проверка игры консервативна: закрой все Minecraft-процессы.
Symlink/junction, пересекающиеся папки и неизвестные/повреждённые форматы отклоняются.
До изменения профиля создаётся копия с SHA-256 каждого файла; конкурентные изменения
исходных файлов прерывают перенос.

## Что входит в копию

- Весь профиль: состояние, очередь, журналы, память, личности и подключения.
- Папка общего разговора Claude: инструкции, память, указатели и настройки.
  Временная блокировка самого переноса не копируется.
- Прежняя привязка Codex, даже если она находится вне профиля.
- `config/agentcraft-client.json`, `config/agentcraft-studio.json`, папки
  `config/agentcraft-skins`, `config/agentcraft`, история игровой консоли.
- `agentcraft-workspace.json`, `agentcraft-anchors.json`, `agentcraft-world.json`,
  `agentcraft-site.json`, `agentcraft-sites.json`, `agentcraft-hq-plan.dat` в одиночных мирах.

Регионы мира, обычные Minecraft-файлы, авторизация и собственные хранилища истории
Codex/Claude не изменяются. Это копия данных AgentCraft, не всего мира или аккаунта.
Нативный разговор остаётся у провайдера по прежнему ID; второй владелец не создаётся.

В профиле появляются `team.json`, два файла подключения и `backend.teamMigration`
в `state.json`. Активация `team.json` выполняется последней. При ошибке записи профиль
восстанавливается из копии. Повтор успешного `apply` ничего не записывает.

## После переноса

Запусти совместимые мост и мод протокола 2. В игре остаются два персонажа и старая
доска. Очередь на паузе; продолжение — отдельное действие пользователя.

До общей очереди ролей перенесённая пара использует прежний механизм планирования/ревью.
Старые карточки, вопросы, ожидание ответа и редактор характеров остаются доступными.
Подключения читаются из записей двух агентов. Прежний курсор Codex и состояние диалога
Claude используются без повторной выдачи старых ответов. Папка Claude и блокировка те же.

Имена, внешность и видимость доступны даже при незавершённых карточках, открытых вопросах
и работающем диалоге. Эти изменения не прерывают выполнение и не переписывают историю
имён исполнителей. Выключение запрещено, пока активна задача очереди или ответ Claude;
отложенные карточки и личная пауза сами по себе выключению не мешают. Это правило действует
и для прежнего пульта, и для `team.update`. Алиасы `codex`/`claude` и адресат `all`
сохраняют прежнюю маршрутизацию пары (`all` — Codex); выключенная Claude по-прежнему
просит включить исполнителя перед сообщением или управлением. Добавление, архивация,
смена провайдера/ролей перенесённой пары запрещены до общей очереди: исполнители старых
карточек не должны незаметно поменяться. Это ограничение не касается чистых команд A2/A3.
После перезапуска Codex можно обновить адрес того же чата подключением с `--agent marlow`.

## Восстановление

Останови работу, мост и Minecraft, верни Claude из внешнего владельца. Выполни ту же
команду с `restore` вместо `apply`, указав ту же копию и те же пути. После проверки
контрольных сумм и свободного состояния текущие данные сохраняются в
`before-restore-<UUID>` внутри копии. Исходные файлы возвращаются побайтно, включая
CRLF и PNG. Новые файлы в управляемых папках профиля/Claude/скинов удаляются оттуда,
но остаются в копии перед откатом. Обычные файлы игры не затрагиваются.
Для старой версии отдельно восстанови совместимые мост и мод из установочной копии.
Если приложение Codex перезапускалось, проверка отката использует обновлённый адрес
того же чата из записи агента. Сама копия возвращает прежние байты привязки; после отката
при необходимости переподключи этот же чат обычным помощником старого моста.

`<профиль>.migration-lock.json` рядом с профилем блокирует запуск моста во время
операции. После аварийного завершения выполни `restore`, прежде чем запускать мост:
он заменяет блокировку только умершего процесса. Если осталась блокировка Claude,
сначала используй существующую команду возврата разговора. При сбое восстановления
исходная проверенная копия остаётся пригодной для повторного `restore`.

Возврат через `Return-Klava-To-Game.cmd` существующей папки или
`Open-Agent.ps1 -Agent wren -Return` пакета вызывает `returnConversation`. Для владельца `game` он снимает блокировку
только после завершения обоих записанных процессов (`pid` и, если указан, `childPid`),
сохраняя сессию и историю. Проверка на синтетической блокировке умершего процесса
переноса включает последующий успешный `restore`. Живой процесс и `EPERM` возврат блокируют.

Проверка PID консервативна и пока не сверяет идентичность процесса: повторно использованный
PID или отказ доступа может блокировать операцию. Не завершай процесс только по номеру
из старого файла. Если после закрытия игры, моста и всех владельцев разговора отказ остаётся,
сверь PID, имя, путь программы и время запуска в диспетчере задач; для `foreman.json` сравни
также `startedAt`. Только подтвердив, что записанный PID относится к постороннему процессу,
сохрани копию и переименуй соответствующий устаревший служебный файл (`foreman.json`,
`portable.json` в профиле или `<профиль>.migration-lock.json` рядом с ним) с суффиксом
`.stale`. Затем повтори **restore** с проверенной копией. Не меняй `state.json`/`team.json`.
Если принадлежность процесса неизвестна или доступ запрещён, не убирай защиту: сначала
восстанови возможность проверить процесс. Автоматического снятия такой блокировки нет.

## Проверки

Тесты используют синтетические данные: полный перенос, точное восстановление,
идемпотентность, паузы, ожидающий ответ, запуск runtime, отказы при активной работе,
занятых сессиях, повреждённой копии, ссылках, конкурентной записи и ошибке активации.
Личный профиль, мир и реальные разговоры пользователя не переносились.
Проверка в запущенном Minecraft остаётся отдельным ручным шагом.

Проверено после исправлений ревью t43: полный Foreman-набор — 761 тест в 43 файлах,
включая 23 теста переноса. Проверены правки внешности при карточках plan/queued/question,
открытом вопросе и работающем диалоге, запрет выключения во время работы, прежние алиасы
и возврат блокировки умершего владельца game с последующим откатом. TypeScript проходит.
Документация протокола актуальна. Переносимый пакет прошёл сборку, аудит содержимого,
изолированную проверку studio и проверки отказов команды переноса без исходных зависимостей.

## Activating the role queue

The migrated pair can opt in to A5 via `queue.enable` in Studio or the settings button.
Resolve old work/questions and pending conversations, then remove personal pauses first.
The new queue imports existing cards and pauses before execution. See [ROLE_QUEUE.md](ROLE_QUEUE.md).

At role-queue activation (and startup of an already migrated profile), the bridge
converts an existing authenticated legacy planning binding to version 2. It validates
both old bindings, the current workspace/session/agent and the intersection of allowed
workspace projects with the board projects. The old workspace file is backed up beside
it before an atomic replacement. The new session-bound permit covers 20 drafts for
24 hours; the queue remains paused. It never approves or starts tasks.

An unfinished queue attempt defers conversion with a notice. After resolving that
attempt, selecting planning retries the conversion. A permit already published to
the workspace remains valid if saving the subsequent status notice fails.

Missing bindings are not invented. Invalid bindings remain untouched with an actionable
queue notice. Existing version 2 bindings, including expired ones, are not renewed on
restart. Operators can explicitly renew them with draft.grant; see ROLE_QUEUE.md.
If the older bridge still reports agentId: expected string, received undefined, update
the bridge or reconnect planning using that operator procedure. Native conversations
and project access do not need to be recreated.

The packaged migration CLI resolves its assets from its own package root; source runs
continue to use the repository root. This avoids rejecting unchanged default characters
because the bundled CLI looked for the cast catalog above the package directory.
