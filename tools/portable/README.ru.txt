AgentCraft — переносимый пакет для Windows

УСТАНОВКА И ПЕРВЫЙ ЗАПУСК
1. Установи Minecraft Java 26.3, Fabric Loader 0.19.5+ и Java 25.
   Нужны Git и собственный Codex (приложение/нативный CLI) либо Claude Code.
   Входы и токены не входят в пакет. Не копируй их в настройки AgentCraft.
2. Распакуй весь пакет. Нужны PACKAGE-READY.json и release-manifest.json.
   Сохрани мир, закрой Minecraft, останови мост. Игра не запускается мастером.
3. Запусти Setup.cmd, выбери русский язык и «Установить / обновить».
   Укажи отдельную ПУСТУЮ папку установки, каталог игры из профиля Fabric и JSON
   выбранной версии Fabric из versions/<версия>/<версия>.json в папке лаунчера.
   Для стороннего лаунчера выбери его JSON метаданных Fabric с inheritsFrom 26.3.
   Мастер проверяет Minecraft/Fabric по этому файлу; профиль запуска в лаунчере
   выбираешь ты. Корни дисков, вложенные друг в друга папки, symlink/junction запрещены.
4. Добавь корневые папки Git-проектов с существующим коммитом и веткой.
   GitHub owner/repo необязателен. Удалённый доступ использует твой gh auth login;
   мастер не выдаёт GitHub-права, не клонирует и не меняет remote проекта.
5. Добавь агентов или оставь команду пустой для настройки в игре.
   Для каждого выбираются имя, Codex приложение / Codex CLI / Claude Code и роли.
   Codex: planner/developer/reviewer. Claude: developer/reviewer; создание планов
   для произвольной команды пока недоступно. Новые агенты остаются выключенными.
   Разные агенты одного провайдера должны иметь разные разговоры.
6. Можно привязать существующий разговор сразу либо через Пульт → Команда.
   Codex Desktop: отдельный threadId и pipePath из выбранного приложения.
   Из авторизованного чата Codex также можно вызвать Connect-Codex.ps1 -Agent <ID>
   после запуска моста. Второй агент не может использовать тот же чат.
   Codex CLI: локальный проект, нативный codex.exe, отдельный UUID подключения
   (мастер создаёт его) и read-only либо workspace-write для разработки.
   Claude: собственное пространство с access.json, инструкциями и conversation.json.
   Мастер может создать новое пространство в workspaces/<ID>. Выполни вход Claude
   самостоятельно, затем запусти в пространстве Start-Session.cmd, напиши сообщение
   и закрой сессию. После этого подключи её путь и sessionId через пульт.
7. «Проверить агента» в Setup работает с остановленным мостом, в игре — через пульт.
   Проверка не вызывает модель и не редактирует проект. Desktop читает чат;
   CLI проверяет версию/команды/вход; Claude проверяет сессию и вход CLI.
   Авторизация SDK разработчика Claude настраивается отдельно средствами провайдера;
   наличие настроек не доказывает работоспособность API. Ключи в мастер не вводятся.
8. Запусти Start-Bridge.cmd ИЗ ПАПКИ УСТАНОВКИ, затем свой профиль Minecraft/Fabric.
   Мост слушает только 127.0.0.1:7878. В творческом инвентаре найди пульт AgentCraft.
   В Команде проверь подключение и включи нужных агентов. Внешность, свои PNG,
   характер, фразы, места, архив и восстановление настраиваются там же.
   Согласуй план перед запуском очереди. Stop-Bridge.cmd останавливает этот мост.
   Install-Mod.cmd — совместимый вход в тот же мастер.

ОБНОВЛЕНИЕ, ОТКАТ И ВОССТАНОВЛЕНИЕ
Распакуй НОВЫЙ пакет отдельно и запусти Setup.cmd оттуда. Не копируй его поверх
использованной установки вручную. Выбери прежнюю папку с installation.json и тот же
каталог игры. Из запущенной установленной копии обновлять её runtime нельзя.
Состав, проекты, team.json, личности, память, привязки, места, скины и настройки
не заменяются шаблонами. Миры не изменяются. Установщик меняет только файлы выпуска
по списку и моды с ID agentcraft/fabric-api, даже если их JAR были переименованы.
Другие моды остаются. Явно включённый в пакет набор схем устанавливается с копией
заменяемых файлов; в обычном выпуске личных схем нет.
Перед заменами создаётся .installer-backups/<операция>: прежние файлы, журнал с
контрольными суммами, копия data и игровых настроек AgentCraft. Внешние папки
провайдеров, их нативные переписки, входы и токены не копируются. Workspaces и миры
сохраняются на месте; резервная копия установки не заменяет их собственный бэкап.
«Откатить» из отдельно распакованного пакета возвращает предыдущие программы/моды.
Текущие пользовательские данные остаются, включая новые записи после обновления.
Это откат файлов выпуска, не автоматическая миграция схем данных. Если старая версия
не читает новый профиль, остановись и используй сохранённый снимок после проверки.
Первая установка не имеет предыдущей версии. Изменённые вручную файлы выпуска
защищены от перезаписи: сохрани и сравни их перед повтором.
При сбое копирования мастер пытается вернуть исходные файлы. При отключении питания
или невозможности возврата остаётся .installer-active.json, блокирующий запуск моста.
Закрой игру/мост и выбери «Восстановить прерванную установку». Не удаляй защитный файл
вручную. Несовпадение контрольных сумм оставляет файлы на месте и требует проверки.
Пакет без installation.json не считается управляемой установкой: выбери новую пустую
папку. Перенос старой пары данных описан ниже, это отдельная операция.
Не распространяй использованную папку установки, data, workspaces или резервные копии.

ПЕРЕНОС СУЩЕСТВУЮЩЕЙ ПАРЫ
Приостанови очередь, заверши/останови активные задачи, закрой Minecraft и останови мост.
Верни общий разговор Claude из терминала/Code. Codex оставь открытым и без активной работы.
Из папки пакета выполни:
  runtime/node.exe migrate-team.mjs apply --profile-dir "D:/AgentCraft/data/observer" --game-dir "D:/Minecraft/Fabric" --codex-binding "D:/AgentCraft/codex-chat.json" --backup-dir "D:/AgentCraft-backups/before-team"
Подставь свои абсолютные пути. Выбери НОВУЮ папку копии вне профиля, игры и папки Claude.
Занятый/непроверенный разговор и активная задача запрещают перенос. Задача модели не запускается.
Symlink/junction и дополнительные настроенные агенты требуют отдельного решения.
Копируются весь профиль, папка Claude, привязка Codex, настройки/скины и метаданные миров
AgentCraft. Два прежних ID, история, ожидающие ответы, приостановленные карточки, личности
и назначения мебели сохраняются. Неиспользуемые стандартные персонажи не добавляются.
Нативная история провайдеров и входы остаются на месте и не копируются.
Старая очередь пары остаётся доступной, сначала на паузе. Состав и роли меняются после явного перехода
на очередь с ролями через queue.enable; имена, внешность и видимость доступны при незавершённых карточках,
открытых вопросах и работающем диалоге. Выключение требует остановки активной задачи очереди
или ответа Claude. Алиасы codex/claude и all → Codex сохранены. Чистые команды не затрагиваются.
Повтор успешного apply ничего не меняет. Для отката останови работу/игру/мост и верни Claude;
повтори ту же команду с restore вместо apply и ТЕМИ ЖЕ путями. Текущие управляемые данные
сначала сохраняются в before-restore-<UUID>, затем возвращаются исходные байты файлов.
Новые файлы в управляемых папках профиля/Claude/скинов удаляются оттуда, но остаются в копии.
Совместимые старые мост/мод при возврате версии восстанавливаются отдельно.
После прерывания используй restore: защитный файл не даст мосту открыть частичный результат.
Штатный возврат разговора снимает и блокировку умершего владельца game, проверив оба PID.
При отказе доступа/повторном использовании PID защита консервативна. Не завершай процесс только
по записанному номеру. Остановив работу, сверь программу, путь и время старта. Только подтвердив,
что процесс посторонний, скопируй и переименуй устаревший foreman.json/portable.json или соседний
<профиль>.migration-lock.json с суффиксом .stale, затем повтори restore. state/team не меняй.
При неизвестной принадлежности процесса защиту оставь до возможности проверки.
Это не полная копия Minecraft-мира или аккаунтов. Не распространяй данные и резервные копии.

НАСТРОЙКИ И ШАБЛОНЫ
В пульте можно задать имя, внешность, характер и фразы. personas.example.json —
нейтральный пример; запускатель копирует его только для нового профиля без personas.json.
Подключение командной версии Claude Code задаётся в редакторе выбранного агента.
Не выбирай исполняемый файл графического приложения вместо Claude Code.
workspace-template содержит нейтральные инструкции, а не готовое подключение Claude.
PROJECTS.md заполняется своими проектами; NOTES.example.md — пустая заготовка заметок.
При отдельной настройке рабочего пространства её можно скопировать как MEMORY.md.
Само копирование шаблонов не выдаёт доступа и не включает общий разговор/планирование.

СВОЙ СКИН PNG
Пульт → «Внешность» → выбери агента → «Загрузить PNG…».
Укажи полный путь к настоящему PNG 64×64, размером не больше 512 КиБ.
Нажми «Применить»; выбери обычные или тонкие руки и отображение внешнего слоя.
Файл копируется в config/agentcraft-skins папки игры под именем SHA-256.png;
исходный PNG можно убрать после импорта. Выбор сохраняется в config/agentcraft-studio.json.
Пользовательский импорт требует 64×64. Для некоторых встроенных скинов 64×32
есть отдельное преобразование старого формата; оно не распространяется на импорт.
Шесть дополнительных пользовательских скинов исключены из публичной сборки.
В частной сборке они могут называться «Скин 1»…«Скин 6»; состав указан в SOURCES.txt.

ПОСТРОЙКИ
Личных построек в обычном пакете нет. Свои .schem помещай в
config/agentcraft/buildings папки игры. /agentcraft preview <имя> показывает объём
и запоминает центр; отойди за границы и введи /agentcraft place <имя>.
Весь объём, включая воздух схемы, заменяет блоки мира. Сначала сохрани резервную копию мира.

ПРОВЕРКИ И ОГРАНИЧЕНИЯ
Сборщик проверяет содержимое пакета, включая вложенные JAR, до отметки готовности.
Личные пути, проекты, переписки, память и аккаунты в исходную поставку не входят.
Лицензии сторонних компонентов сохраняются без изменений, включая авторские контакты.
Сборка и проверка импорта PNG не заменяют проверку отображения в самой игре.
При потере связи статусы не являются подтверждением завершения задачи.
Разрешения и возможности конкретного провайдера зависят от его собственного приложения.

ОЧЕРЕДЬ С РОЛЯМИ
В плане выбери проект, разработчика и ревьюера либо отметь «Без ревью».
Автоматический выбор агентов включается отдельно в настройках.
После согласования плана запусти очередь. Её пауза прекращает новые назначения;
кнопки карточки агента управляют его реальным исполнением.
После перезапуска незаконченная работа требует проверки, а не автоповтора.
Подробности, команды и полномочия провайдеров: ROLE_QUEUE.md.
